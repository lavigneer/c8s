# config/

Kubernetes configuration manifests for C8S deployment.

## Overview

The `config/` directory contains all Kubernetes manifests used for deploying and configuring C8S components. These manifests are organized by type and generated using Kubebuilder.

**Note**: For production deployments, use the [Helm chart](../chart/c8s/) instead of these raw manifests. These files are primarily used for:
- Development and testing
- Kubebuilder code generation
- Understanding the underlying Kubernetes resources
- Tilt local development workflow

## Directory Structure

```
config/
├── crd/                    # Custom Resource Definitions
├── rbac/                   # Role-Based Access Control
├── manager/                # Controller deployment configuration
├── webhook/                # Webhook service configuration
└── samples/                # Sample CRs for testing
```

## Subdirectories

### crd/

**Purpose**: Custom Resource Definitions (CRDs) for C8S.

**Generated by**: `make manifests` (uses controller-gen from Kubebuilder)

**Contents**:
```
crd/
└── bases/
    ├── c8s.dev_pipelineconfigs.yaml     # PipelineConfig CRD
    └── c8s.dev_pipelineruns.yaml        # PipelineRun CRD
```

**Key CRDs**:
- **PipelineConfig**: Defines pipeline configuration (steps, dependencies, resources)
- **PipelineRun**: Represents a single pipeline execution instance

**Usage**:
```bash
# Apply CRDs to cluster
kubectl apply -f config/crd/bases/

# Verify CRDs are installed
kubectl get crds | grep c8s.dev

# View CRD schema
kubectl explain pipelineconfig
kubectl explain pipelinerun
```

**Regeneration**:
```bash
# Regenerate CRDs after modifying types in pkg/apis/v1alpha1/
make manifests
```

---

### rbac/

**Purpose**: Role-Based Access Control (RBAC) manifests for C8S components.

**Documentation**: See [rbac/README.md](./rbac/README.md) for detailed RBAC configuration.

**Contents**:
- Service accounts for controller, webhook, and API server
- Cluster roles with required permissions
- Role bindings to associate roles with service accounts

**Key Files**:
```
rbac/
├── role.yaml                # ClusterRole for controller
├── role_binding.yaml        # ClusterRoleBinding
└── service_account.yaml     # ServiceAccounts
```

**Permissions**:
- **Controller**: Watch/update PipelineConfigs and PipelineRuns, create/manage Jobs and Pods
- **Webhook**: Validate PipelineConfig CRs on create/update
- **API Server**: Read PipelineConfigs, PipelineRuns, and Pods

---

### manager/

**Purpose**: Controller deployment configuration.

**Contents**:
```
manager/
├── deployment.yaml          # Controller Deployment manifest
├── rbac.yaml               # Controller RBAC rules
└── serviceaccount.yaml     # Controller ServiceAccount
```

**Key Configuration**:
- **Image**: `ghcr.io/org/c8s-controller:latest`
- **Replicas**: 1 (single controller instance)
- **Resources**: 100m CPU, 128Mi memory (requests)
- **Health Checks**: Liveness and readiness probes

**Deployment**:
```bash
# Apply controller deployment
kubectl apply -f config/manager/

# Check controller status
kubectl get deployment c8s-controller -n c8s-system
kubectl logs -f deployment/c8s-controller -n c8s-system
```

**Notes**:
- For production, use Helm chart which provides more configuration options
- Controller watches for PipelineRun CRs and creates Kubernetes Jobs
- Requires CRDs to be installed first

---

### webhook/

**Purpose**: Admission webhook configuration for validating PipelineConfig CRs.

**Contents**:
```
webhook/
└── validatingwebhookconfiguration.yaml
```

**Functionality**:
- Validates PipelineConfig YAML syntax
- Ensures required fields are present
- Validates step dependencies (no cycles)
- Checks resource limit formats

**Configuration**:
```yaml
webhooks:
  - name: vpipelineconfig.c8s.dev
    clientConfig:
      service:
        name: c8s-webhook
        namespace: c8s-system
        path: /validate-c8s-dev-v1alpha1-pipelineconfig
    rules:
      - apiGroups: ["c8s.dev"]
        apiVersions: ["v1alpha1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["pipelineconfigs"]
```

**Deployment**:
```bash
# Apply webhook configuration
kubectl apply -f config/webhook/

# Verify webhook is registered
kubectl get validatingwebhookconfigurations | grep c8s
```

**TLS Requirements**:
- Webhook requires TLS certificates
- See [webhook-tls-guide.md](../docs/operations/webhook-tls-guide.md) for setup
- Certificates can be managed manually or with cert-manager

### samples/

**Purpose**: Example Custom Resources for testing and development.

**Contents**:
```
samples/
├── pipelineconfig_example.yaml      # Basic PipelineConfig example
├── pipelineconfig-c8s.yaml         # C8S self-hosting (dogfooding)
├── pipelinerun_example.yaml         # Manual PipelineRun trigger
├── multi-step.yaml                  # Multi-step pipeline with dependencies
└── matrix-build.yaml                # Matrix build example
```

**Usage**:
```bash
# Create a PipelineConfig
kubectl apply -f config/samples/pipelineconfig_example.yaml

# Verify it was created
kubectl get pipelineconfigs

# Trigger a pipeline run
kubectl apply -f config/samples/pipelinerun_example.yaml

# Watch pipeline execution
kubectl get pipelineruns -w
kubectl get jobs -l c8s.dev/pipeline=my-pipeline
```

**Example PipelineConfig**:
```yaml
apiVersion: c8s.dev/v1alpha1
kind: PipelineConfig
metadata:
  name: example-pipeline
spec:
  repository: https://github.com/org/repo
  branches:
    - main
  steps:
    - name: test
      image: golang:1.25
      commands:
        - go test ./...
      resources:
        cpu: 1000m
        memory: 2Gi
```

## Generating Manifests

### Using Kubebuilder

The config/ directory follows Kubebuilder project structure. Manifests are generated from:
- Go type definitions in `pkg/apis/v1alpha1/`
- Kubebuilder markers (comments like `// +kubebuilder:...`)

**Common Commands**:
```bash
# Generate CRD manifests
make manifests

# Install CRDs to cluster
make install-crds

# Apply all config (development)
kubectl apply -k config/default
```

### Kustomize

The config/ directory is organized for Kustomize:
```bash
# Build complete manifest
kubectl kustomize config/default > c8s-all.yaml

# Apply with Kustomize
kubectl apply -k config/default
```

## Deployment Methods

### Method 1: Helm Chart (Recommended)

Use the Helm chart for production deployments:
```bash
helm install c8s ./chart/c8s -n c8s-system --create-namespace
```

See [chart/c8s/README.md](../chart/c8s/README.md) for details.

### Method 2: Tilt (Local Development)

Use Tilt for local development with live reload:
```bash
tilt up
```

See [docs/development/TILT-WORKFLOW.md](../docs/development/TILT-WORKFLOW.md) for details.

### Method 3: Raw Manifests (Testing Only)

Apply manifests directly (for testing and development):
```bash
# 1. Create namespace
kubectl create namespace c8s-system

# 2. Install CRDs
kubectl apply -f config/crd/bases/

# 3. Install RBAC
kubectl apply -f config/rbac/

# 4. Deploy controller
kubectl apply -f config/manager/

# 5. Deploy webhook (requires TLS certs)
kubectl apply -f config/webhook/
```

## Customization

### For Development

Edit manifests in config/ for local testing, but **do not commit** these changes. Instead:
1. Make changes in Helm chart values
2. Use Kustomize overlays
3. Update Go type definitions and regenerate

### For Production

Customize via Helm chart values:
```yaml
# chart/c8s/values.yaml
controller:
  replicas: 3
  resources:
    requests:
      cpu: 500m
      memory: 512Mi
```

## Validation

### Validate Manifests

```bash
# Validate YAML syntax
yamllint config/

# Dry-run apply
kubectl apply --dry-run=client -f config/crd/bases/
kubectl apply --dry-run=server -f config/manager/

# Kubebuilder validation
make test
```

### Test CRD Changes

```bash
# Apply CRDs
make install-crds

# Test with sample CR
kubectl apply -f config/samples/pipelineconfig_example.yaml

# Verify CR is accepted
kubectl get pipelineconfigs
kubectl describe pipelineconfig example-pipeline
```

## Troubleshooting

### CRD Installation Issues
```bash
# Check if CRDs exist
kubectl get crds | grep c8s.dev

# View CRD details
kubectl describe crd pipelineconfigs.c8s.dev

# Reinstall CRDs
kubectl delete -f config/crd/bases/
kubectl apply -f config/crd/bases/
```

### RBAC Issues
```bash
# Check service accounts
kubectl get sa -n c8s-system

# Check roles and bindings
kubectl get clusterrole | grep c8s
kubectl get clusterrolebinding | grep c8s

# View effective permissions
kubectl auth can-i --list --as=system:serviceaccount:c8s-system:c8s-controller
```

### Webhook Issues
```bash
# Check webhook configuration
kubectl get validatingwebhookconfigurations

# View webhook logs
kubectl logs -f deployment/c8s-webhook -n c8s-system

# Test validation (should fail if required fields missing)
kubectl apply -f - <<EOF
apiVersion: c8s.dev/v1alpha1
kind: PipelineConfig
metadata:
  name: invalid
spec: {}  # Missing required fields
EOF
```
