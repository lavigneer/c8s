# C8S Package Structure

This directory contains all shared libraries and business logic for the C8S continuous integration system.

## Package Overview

```
pkg/
├── api/              # REST API handlers and middleware
├── apierrors/        # Error types and HTTP error handling
├── apis/v1alpha1/    # Kubernetes CRD type definitions
├── auth/             # Authentication and authorization (JWT)
├── cache/            # Caching layer for pipeline data
├── config/           # Configuration management
├── controller/       # Kubernetes controller logic (watches PipelineRuns)
├── dashboard/        # Dashboard-specific data transfer objects
├── logstorage/       # Log storage abstraction (S3-compatible)
├── metrics/          # Prometheus metrics instrumentation
├── pagination/       # API pagination helpers
├── parser/           # Pipeline YAML parsing and validation
├── scheduler/        # DAG scheduler for pipeline steps
├── secrets/          # Kubernetes Secret management
├── sse/              # Server-Sent Events for real-time log streaming
├── storage/          # S3-compatible artifact storage
├── types/            # Shared type definitions
└── webhook/          # Git webhook handlers (GitHub, GitLab, Bitbucket)
```

## Package Descriptions

### API Layer

#### `api/`
HTTP API handlers and middleware for the C8S REST API server.
- **Purpose**: RESTful endpoints for pipeline management, log retrieval, artifact access
- **Key Files**: handlers for pipelines, runs, logs, artifacts, projects
- **Dependencies**: auth/, apierrors/, dashboard/, logstorage/, storage/

#### `apierrors/`
Centralized error types and HTTP error response handling.
- **Purpose**: Consistent error responses across API endpoints
- **Key Files**: error types, HTTP status code mapping, error formatting
- **Dependencies**: None (foundational package)

#### `sse/`
Server-Sent Events implementation for real-time log streaming.
- **Purpose**: Push real-time pipeline logs to dashboard clients
- **Key Files**: SSE connection management, event formatting
- **Dependencies**: logstorage/

### Core Domain Logic

#### `apis/v1alpha1/`
Kubernetes Custom Resource Definitions (CRDs) for C8S.
- **Purpose**: Type-safe Go structs for PipelineConfig, PipelineRun, RepositoryConnection
- **Key Files**: CRD types, DeepCopy methods (auto-generated), validation webhooks
- **Dependencies**: None (Kubernetes API types only)
- **Note**: Files with `zz_generated` prefix are auto-generated by controller-gen

#### `controller/`
Kubernetes controller that watches PipelineRun CRDs and creates Kubernetes Jobs.
- **Purpose**: Core orchestration logic - converts PipelineRun → Kubernetes Jobs
- **Key Files**: PipelineRun reconciler, Job manager, status updates
- **Dependencies**: apis/v1alpha1/, scheduler/, logstorage/, secrets/

#### `scheduler/`
DAG (Directed Acyclic Graph) scheduler for pipeline step dependencies.
- **Purpose**: Resolves step dependencies and determines execution order
- **Key Files**: Dependency graph builder, topological sort, parallel execution planning
- **Dependencies**: apis/v1alpha1/, types/

#### `parser/`
Pipeline YAML parsing and validation.
- **Purpose**: Parse .c8s.yaml files into PipelineConfig CRDs
- **Key Files**: YAML unmarshaling, schema validation, default value injection
- **Dependencies**: apis/v1alpha1/

### Authentication & Security

#### `auth/`
Authentication and authorization using JWT tokens.
- **Purpose**: Secure API endpoints, validate user identity and permissions
- **Key Files**: JWT generation/validation, middleware, user session management
- **Dependencies**: secrets/

#### `secrets/`
Kubernetes Secret management for pipeline steps.
- **Purpose**: Inject secrets as environment variables into pipeline Job Pods
- **Key Files**: Secret resolution, environment variable injection, secret masking in logs
- **Dependencies**: apis/v1alpha1/

### Data Management

#### `cache/`
In-memory caching layer for frequently accessed pipeline data.
- **Purpose**: Reduce database/API calls for pipeline status and metadata
- **Key Files**: Cache interface, TTL management, cache invalidation
- **Dependencies**: apis/v1alpha1/

#### `config/`
Application configuration management.
- **Purpose**: Load and validate configuration from environment variables and config files
- **Key Files**: Config struct, validation, defaults
- **Dependencies**: None

#### `dashboard/`
Data transfer objects (DTOs) and helpers specific to the dashboard UI.
- **Purpose**: Transform CRD data into dashboard-friendly formats
- **Key Files**: Pipeline run DTOs, project aggregation, statistics calculation
- **Dependencies**: apis/v1alpha1/, pagination/

#### `types/`
Shared type definitions used across multiple packages.
- **Purpose**: Common types and interfaces to reduce coupling
- **Key Files**: Shared structs, enums, constants
- **Dependencies**: None (foundational package)

### Storage

#### `logstorage/`
Abstraction layer for pipeline log storage.
- **Purpose**: Store and retrieve pipeline logs from S3-compatible storage
- **Key Files**: S3 client wrapper, log upload/download, log aggregation
- **Dependencies**: storage/

#### `storage/`
S3-compatible artifact and log storage.
- **Purpose**: Persistent storage for build artifacts and execution logs
- **Key Files**: S3 client, presigned URL generation, object listing
- **Dependencies**: config/

### External Integrations

#### `webhook/`
Git webhook handlers for GitHub, GitLab, and Bitbucket.
- **Purpose**: Receive webhook events and create PipelineRun CRDs
- **Key Files**: Webhook signature validation, event parsing, PipelineRun creation
- **Dependencies**: apis/v1alpha1/, parser/

### Observability

#### `metrics/`
Prometheus metrics instrumentation.
- **Purpose**: Expose operational metrics for monitoring and alerting
- **Key Files**: Metric definitions, metric collection, Prometheus registry
- **Dependencies**: None

#### `pagination/`
API pagination helpers for large result sets.
- **Purpose**: Paginate API responses consistently across endpoints
- **Key Files**: Page calculation, limit/offset handling, pagination metadata
- **Dependencies**: None

## Dependency Guidelines

### Package Dependency Rules

1. **No Circular Dependencies**: Packages must not depend on each other in a circular manner
2. **Layered Architecture**: Higher-level packages can depend on lower-level, not vice versa
3. **Minimize Cross-Package Coupling**: Use interfaces and dependency injection where possible

### Dependency Layers (Low to High)

**Layer 1 (Foundation)**: No dependencies on other pkg/ packages
- apierrors/, config/, types/, pagination/, metrics/

**Layer 2 (Core Domain)**: Depends only on Layer 1
- apis/v1alpha1/, parser/, scheduler/

**Layer 3 (Business Logic)**: Depends on Layers 1-2
- auth/, secrets/, cache/, storage/, logstorage/, webhook/

**Layer 4 (Application)**: Depends on all layers
- controller/, api/, dashboard/, sse/

## Adding New Packages

When adding a new package to `pkg/`:

1. **Choose a Clear Name**: Use lowercase, descriptive names (e.g., `retrypolicy`, not `retry_policy`)
2. **Document Purpose**: Add README.md or package-level doc comment
3. **Minimize Dependencies**: Only depend on packages you truly need
4. **Export Interfaces**: Define interfaces for testability and flexibility
5. **Update This README**: Add your package to the overview and descriptions above

## Testing

Each package should include:
- Unit tests: `*_test.go` files alongside source
- Integration tests: `tests/integration/<package>/` (for packages requiring Kubernetes or external services)
- Mocks: `<package>/mock/` or `tests/testutil/mocks/<package>/`

Run tests:
```bash
# Test single package
go test ./pkg/parser/...

# Test all packages
make test

# Test with coverage
make coverage
```
